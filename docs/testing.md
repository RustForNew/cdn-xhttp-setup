# Тестирование

## Локальные проверки

Из папки проекта, в отдельном Python-окружении:

```bash
python -m pip install -e . pytest cryptography
python -m pytest -q
python -m compileall -q cdn_xhttp
```

Тесты проверяют ввод данных, формирование ссылок, параметры одного и двух серверов, уникальные UUID, сохранение файлов, SSH-установщик и обработку ошибок. Проверка HTTP использует локальную службу и сверяет полученные данные по SHA256.

Регрессии мастера покрывают Y/N и опечатки, выбор моста первым вопросом, повтор неверного поля, передачу паролей нужному VPS без записи в файлы, отсутствие секретов в сообщениях об ошибках, отмену и продолжение с теми же UUID, резервную копию и прерывание новой настройки. SSH-вызовы в этих тестах заменены заглушками. Тесты запуска проверяют повторное использование окружения, обновление зависимостей при изменении метаданных и обработку ошибок подготовки.

Часть тестов установщика требует Bash. На Windows они используют Git Bash при его наличии; пропущенные тесты видны в отчёте pytest.

## Проверка настоящим Xray

Скачайте [официальный Xray 26.5.9](https://github.com/XTLS/Xray-core/releases/tag/v26.5.9) для своего компьютера и сверьте SHA256 архива. Укажите путь к распакованному бинарнику:

```bash
python tests/smoke_xray.py --xray /path/to/xray
```

На Windows укажите путь к `xray.exe`.

Сценарий запускает Xray-клиент, origin и при необходимости exit во временных папках на локальных портах. Он проверяет четыре сочетания: один/два сервера и `fast`/`original`. Переданные данные сверяются по SHA256. Соединение с exit использует TLS + Vision.

Локальный HTTP-прокси заменяет CDN и Nginx: сохраняет padding и преобразует OPTIONS в POST. Участок клиент → локальный прокси работает без TLS. Поэтому этот тест не подтверждает работу конкретного CDN, выпуск публичных сертификатов или скорость интернета.

## Проверка на VPS

Для проверки полной схемы нужны готовый CDN, домены и отдельный VPS. Для режима двух серверов нужен дополнительный exit.

1. Выполните `plan` и проверьте адреса, конфиги и порты до установки.
2. Выполните `deploy`. Убедитесь, что сертификаты выпущены, службы работают, а `nginx -t` и `xray run -test` завершаются успешно.
3. Выполните `check`: origin и CDN должны передавать тело OPTIONS без изменений, включая пакет в 1 000 000 байт.
4. Импортируйте ссылку в клиент с поддержкой XHTTP extra. Проверьте отправку и получение файлов, внешний IP и отказ в доступе с незарегистрированным UUID.
5. Повторите `deploy` с сохранённым `deployment.json`: UUID и доступ должны сохраниться.
6. Проверьте продление сертификатов командой `certbot renew --dry-run`. Отдельно проверьте перечитывание сертификата службами и копирование на exit: тестовое продление не всегда запускает deploy-hook.
7. На одноразовом VPS проверьте восстановление после ошибки установки.

Для сравнения скорости используйте одинаковый клиент и направление, минимум три передачи файлов по 20–100 МБ в обе стороны для каждого профиля. Записывайте скорость и ошибки; меньший интервал сам по себе не доказывает прирост скорости.

## Границы совместимости

Установщик рассчитан на Ubuntu 22.04/24.04, amd64/arm64 и systemd. Установка и прямое подключение к origin проверены на Ubuntu 22.04 и 24.04 amd64. На Ubuntu 24.04 также проверены два UUID, передача по 1 000 000 байт с совпадением SHA256, выход в интернет через VPS, отказ незарегистрированному UUID и тестовое продление сертификата с deploy-hook.

На одном готовом ресурсе Yandex Cloud CDN проверены HTTPS, передача OPTIONS и полное VLESS-подключение к origin на Ubuntu 24.04: две учётные записи, целостность отправленных данных, выходной IP и отказ неизвестному UUID. Проверки прошли по двум сетевым маршрутам. Это функциональная проверка, а не измерение скорости или гарантия доступности всех узлов CDN.

arm64, два физических VPS и импорт в конкретные клиентские приложения требуют отдельной проверки. Работу через CDN нужно проверять отдельно для выбранного ресурса и сети пользователя: успешное прямое подключение к origin её не подтверждает. Успех локальных тестов не заменяет такую проверку.
