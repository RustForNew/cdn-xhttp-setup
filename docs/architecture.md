# Архитектура и контракты

Техническая справка для разработчиков. Для установки достаточно [основной инструкции](../README.md).

## Компоненты

Программа запускается на Windows или Linux и настраивает VPS по SSH через Paramiko. CDN и DNS должны быть готовы заранее. Создание облачных ресурсов в программу не входит.

| Модуль | Назначение |
| --- | --- |
| `config.py` | Проверка и сохранение параметров |
| `render.py` | Конфиги Xray, Nginx и VLESS-ссылки |
| `remote.py` | Передача установочного скрипта по SFTP и запуск через root/sudo |
| `health.py` | Проверка HTTPS и передачи данных через CDN |
| `cli.py` | Мастер настройки и команды |

## Конфигурация

`deployment.json` использует схему версии 1. Неизвестные поля отклоняются. SSH-пароли и пароли sudo не сохраняются.

- `name`: название ссылок, 1–80 символов без управляющих символов.
- `uuids`: от 1 до 1000 уникальных UUID — идентификаторов доступа. Мастер создаёт их случайным образом.
- `uuid`: первый UUID; конфиги с единственным полем `uuid` также поддерживаются.
- `profile`: `fast` или `original`, меняет интервал отправки клиента.

Повторная установка использует сохранённые UUID. Все UUID добавляются в конфиг сервера; несколько ссылок получают номера в названии. Это отдельные учётные данные без индивидуальных квот трафика.

## Схемы подключения

```text
Один VPS: клиент → CDN → origin → интернет
Два VPS:  клиент → CDN → origin → exit → интернет
```

Origin — сервер, принимающий трафик от CDN. Exit — необязательный второй сервер для выхода в интернет.

Клиент подключается к CDN-домену на порту 443. Адрес, Host и TLS SNI равны CDN-домену, проверка сертификата включена. CDN обращается к origin по HTTPS. Nginx на origin завершает TLS и передаёт XHTTP в Xray на `127.0.0.1:8003`.

В режиме одного VPS Xray отправляет трафик напрямую через `freedom`. В режиме двух VPS origin соединяется с exit по VLESS TCP + TLS + `xtls-rprx-vision` на порту 10443. Для TLS используется exit-домен, для авторизации — первый UUID. Резервного прямого выхода с origin нет. Сертификаты CDN, origin и exit независимы.

Оба VPS в двухсерверном режиме должны использовать одну семью IP-адресов. Все A/AAAA-записи origin и exit должны совпадать с указанным адресом соответствующего VPS. Автоматическая настройка NAT не поддерживается.

## XHTTP и отправка данных

Основные параметры клиента:

```json
{
  "mode": "packet-up",
  "scMaxEachPostBytes": 1000000,
  "scMinPostsIntervalMs": 5,
  "scMaxBufferedPosts": 30,
  "xPaddingObfsMode": true,
  "xPaddingKey": "dc",
  "xPaddingHeader": "X-Cache",
  "xPaddingMethod": "tokenish",
  "xPaddingPlacement": "queryInHeader",
  "uplinkHTTPMethod": "OPTIONS"
}
```

Путь по умолчанию — `/api-test`. Параметры padding совпадают на клиенте и сервере. Padding добавляет служебное заполнение; CDN должен сохранять заголовок `X-Cache` и тело запроса.

Nginx заменяет OPTIONS на POST только для XHTTP: [Xray 26.5.9 обрабатывает OPTIONS отдельно](https://github.com/XTLS/Xray-core/blob/v26.5.9/transport/internet/splithttp/hub.go). Буферизация запросов и ответов выключена. Лимит тела 2 MiB превышает максимальный XHTTP-пакет в 1 000 000 байт. Большие буферы заголовков обеспечивают передачу padding; старые HTTP/2-директивы оставлены для Nginx 1.18 и могут вызывать предупреждения на более новых версиях.

Профиль `fast` задаёт паузу 5 мс, `original` — 30 мс. Остальные поля одинаковы. Ноль не используется: [Xray трактует его как 30 мс](https://github.com/XTLS/Xray-core/blob/v26.5.9/transport/internet/splithttp/config.go). Меньшая пауза уменьшает программную задержку и может увеличить число запросов; фактическая скорость зависит от сети и CDN. `scMaxBufferedPosts` задаёт серверную очередь переупорядочивания.

VLESS-ссылка содержит параметры в JSON-поле `extra` с URL-кодированием. Если клиент теряет их при импорте, можно использовать полный `client.json`. [Описание формата VLESS URI](https://github.com/XTLS/Xray-core/discussions/716).

## Проверка соединения

Путь `/cdn-check` направляет OPTIONS в диагностическую службу на `127.0.0.1:8004`. Служба возвращает метод, длину и SHA256 полученного тела. Проверка отправляет случайные 4 байта и 1 000 000 байт, сверяет ответ и сертификат TLS. Кеширование и перенаправления не допускаются.

В `status.json` поле `endpoint_verified` означает успешную проверку HTTPS и передачи OPTIONS. Поле `vless_tunnel_verified` при этой проверке остаётся `false`: авторизацию VLESS, длительную передачу и скорость нужно проверять клиентом.

## Версия Xray

По умолчанию закреплена [26.5.9](https://github.com/XTLS/Xray-core/releases/tag/v26.5.9). Установщик скачивает подходящий бинарник для amd64/arm64 и сверяет SHA256 с официальным файлом контрольных сумм. Сторонние установочные скрипты не запускаются. Автоматического обновления Xray нет.
